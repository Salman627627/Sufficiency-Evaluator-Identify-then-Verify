# Information Sufficiency Evaluator

An autonomous Django + React implementation and evaluation framework for **"Knowing What's Missing: Assessing Information Sufficiency in Question Answering"** (Akriti Jain & Aparna Garimella, Adobe Research, *Findings of EACL 2026*).

The application evaluates whether a given context contains sufficient information to answer complex multi-hop questions from the HotpotQA dataset. It implements the **Identify-then-Verify** framework and contrasts it against two established baselines (**Autorater** and **MIGRES**) and an ablation (**Identify-only**).

---

## Architecture & Evaluation Protocol

For each question, two evaluation cases are constructed following the paper's methodology:
1. **Full context**: Gold supporting-fact passages + distractor paragraphs &rarr; Expected **Sufficient**.
2. **Ablated context**: One gold supporting-fact passage removed &rarr; Expected **Insufficient**.

### Four Methods Implemented

1. **Autorater** (Baseline): Direct one-shot prompt asking the model to classify context sufficiency as `SUFFICIENT` or `INSUFFICIENT` with a one-sentence justification.
2. **MIGRES** (Baseline): Reformulates sufficiency as a QA task where the model attempts to answer using *only* the context. If unanswerable, it outputs `unanswerable` and summarizes the gap (`unanswerable` &rarr; `Insufficient`, otherwise `Sufficient`).
3. **Identify-only** (Ablation):
   - Samples $N=5$ hypotheses about missing information at temperature $T=0.5$.
   - Computes pairwise cosine similarity embeddings to establish semantic consensus.
   - Selects the hypothesis closest to the semantic centroid (the **Consensus Gap Claim**). If average similarity $< 0.3$, defaults to `Insufficient`.
   - Predicts `Sufficient` only if consensus states *"No information is missing"*, else `Insufficient`.
4. **Identify-then-Verify** (Proposed Framework):
   - Extends Identify-only with an independent verification check on the Consensus Gap Claim.
   - Prompts the LLM: *"Is the claimed missing information actually present in the context? Synonyms, paraphrase, and reasonable inference count. Reply YES or NO."*
   - `YES` (found in context) &rarr; `Sufficient` (self-corrects hallucinated gap).
   - `NO` (truly absent) &rarr; `Insufficient`.
   - If consensus already indicates nothing is missing, skips verification and directly outputs `Sufficient`.

## Setup & Running

### Prerequisites
- Python $\ge$ 3.10
- Node.js $\ge$ 18 (npm $\ge$ 9)

### 1. Backend Setup (Django)
```bash
# Navigate to backend directory
cd backend

# Create and activate virtual environment (optional but recommended)
python -m venv .venv
# On Windows PowerShell:
.\.venv\Scripts\Activate.ps1
# On Linux/macOS:
source .venv/bin/activate

# Install dependencies (only Django required; sentence-transformers optional)
pip install -r requirements.txt

# Run migrations and start development server on port 8000
python manage.py migrate
python manage.py runserver 127.0.0.1:8000
```
Backend API will be running at `http://127.0.0.1:8000/`.

### 2. Frontend Setup (React 18 + Vite)
```bash
# In a new terminal, navigate to frontend directory
cd frontend

# Install npm packages
npm install

# Start Vite dev server on port 5173
npm run dev
```
Open your browser at `http://localhost:5173/`. Vite automatically proxies `/api/*` requests to `http://127.0.0.1:8000`.

## LLM Modes: Real vs. Mock

### 1. Mock Mode (Default - Zero Configuration)
When `LLM_API_KEY` is not set, the app runs completely offline using an internal keyword-overlap and stem heuristic.
- Simulates temperature variations by introducing a 30% rate of hallucinated gap claims at $T > 0$.
- Allows testing the full UI, pipeline, consensus aggregation, and verification self-correction offline.

> [!WARNING]
> **Demo Only**: Mock mode numbers are generated by offline heuristics for demonstration and testing. They must not be cited as empirical paper benchmarks.

### 2. Real LLM Mode (OpenAI, Ollama, Groq, etc.)
The backend LLM layer uses standard Python `urllib` to query any OpenAI-compatible `/chat/completions` endpoint. Set the following environment variables before running `manage.py runserver`:

#### OpenAI
```bash
export LLM_API_KEY="sk-..."
export LLM_MODEL="gpt-4o-mini"
# LLM_BASE_URL defaults to https://api.openai.com/v1
```

#### Ollama (Local LLM)
```bash
export LLM_API_KEY="ollama"
export LLM_BASE_URL="http://localhost:11434/v1"
export LLM_MODEL="llama3.1:8b"
```

#### Groq
```bash
export LLM_API_KEY="gsk_..."
export LLM_BASE_URL="https://api.groq.com/openai/v1"
export LLM_MODEL="llama-3.1-8b-instant"
```

*(On Windows PowerShell, use `$env:LLM_API_KEY="sk-..."`)*

### Semantic Embeddings (Optional)
By default, semantic consensus uses an internal normalized bag-of-words cosine fallback that requires no external libraries. For neural sentence embeddings as described in the paper, install:
```bash
pip install sentence-transformers
```
When installed, `all-MiniLM-L6-v2` is automatically loaded for embedding consensus hypotheses.

## API Reference

All endpoints return JSON and enforce strict HTTP method handling (CSRF exempt on POST).

| Endpoint | Method | Description |
| :--- | :--- | :--- |
| `/api/health/` | `GET` | Health status, active `llm_mode` (`"mock"` or `"remote"`), and available `methods`. Returns 405 on non-GET. |
| `/api/samples/` | `GET` | Returns list of built-in HotpotQA samples with gold and distractor passages. Returns 405 on non-GET. |
| `/api/evaluate/` | `POST` | Evaluates selected samples and methods. Body: `{"sample_ids": [...], "methods": [...], "custom": [...]}`. Saves a `Run` record and returns `{run_id, mode, summary, cases}`. Returns 400 for empty selection / invalid JSON. |
| `/api/runs/` | `GET` | Returns the 20 most recent evaluation runs with timestamps, modes, and summaries. |
